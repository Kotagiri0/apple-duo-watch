# Мониторинг: страница состояния и Prometheus на сервере в Германии

Четыре контейнера на сервере в Германии (`188.213.0.80`), все порты только на
`127.0.0.1`. Ничего не публикуется наружу: страницу открывают через SSH-туннель.

| Контейнер | Что делает | Порт (только loopback) |
|---|---|---|
| `prometheus` | собирает метрики, хранит 30 дней (не больше 1 ГБ) | 9090 |
| `node-exporter` | ЦП, ОЗУ, диск, нагрузка сервера | 9100 |
| `fleet-exporter` | состояние наблюдателей, резерва, деадмана, сайтов, Apple | 9877 |
| `status-page` | HTML-страница, строится из данных Prometheus | 8080 |

## Как смотреть страницу

С Mac, в терминале:

```bash
ssh -L 8080:127.0.0.1:8080 -i ~/.ssh/duo_tunnel root@188.213.0.80
```

Пока туннель открыт, в браузере: <http://127.0.0.1:8080>. Страница сама
обновляется раз в минуту.

## Что на странице

- **Серверы.** Сервер в Германии: ЦП, ОЗУ, диск, нагрузка, контейнеры, службы.
  NanoPi и ПК: открыт ли порт SSH. Открытый порт означает, что машина на связи,
  но не то, что на ней работает наблюдатель: heartbeat не различает источник.
- **Наблюдатели.** Возраст последнего heartbeat, режим резерва (тихий или
  перехват), неудачи подряд, деадман, счётчики журнала резерва.
- **Apple UAE.** Восемь конфигураций: цена, ранний срок, можно ли заказать
  сейчас, сколько магазинов готовы отдать телефон сейчас.
- **Аналитика.** Доля времени с живым heartbeat, опросы Apple в час, сдвиг
  самого раннего срока за неделю, графики ЦП, ОЗУ и heartbeat.

Вердикт: зелёный, жёлтый («есть вопросы») или красный («никто не ведёт
доставку»). Красный появляется только тогда, когда основной молчит и резерв не
перехватил доставку.

## Что здесь не делается

- Ничего не покупается и не меняется в оплате.
- Токены, chat id и ники на страницу не попадают. В тестах это проверяется.
- Журнал резерва только считается по типам событий, сами строки не публикуются.
- Самовывоз считается по формулировке Apple. «Check back for availability on
  23/10» — это будущая дата, а не наличие, и в счёт не идёт (как и в
  `watcher.py`, функция `pickup_available`).

## Обновление и остановка

```bash
cd /opt/duo-monitoring
docker compose up -d            # поднять или обновить
docker compose restart status-page fleet-exporter
docker compose down             # остановить всё (данные Prometheus сохранятся)
```

Файлы копируются с Mac из `deploy/monitoring/`. Образы закреплены по версиям:
`prom/prometheus:v2.55.1`, `prom/node-exporter:v1.8.2`, `python:3.12-slim`.

## Проверка без страницы

```bash
curl -s http://127.0.0.1:9090/api/v1/targets | python3 -m json.tool | grep -E '"job"|"health"'
curl -s http://127.0.0.1:9877/metrics | grep '^duo_' | head
```

## Тесты

```bash
python3 -I -m unittest discover -s tests -p 'test_monitoring.py' -v
```

Тесты не требуют сети и Docker: разбор журнала, ротация, решение о вердикте,
подсчёт самовывоза по формулировкам Apple и то, что страница не выводит секреты.
